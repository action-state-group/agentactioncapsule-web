Use-case evidence: twins and a referee

Seam ③ Check/judge. Build: a sampled twin comparison and a signed referee ruling. Conform to: draft-mih-agent-bilateral-attestation-02 and draft-mih-agent-evidence-layer-00 §4.1, §5.

Sending a request to two nodes and comparing the answers tells you how often a pairing disagrees; asking a third node to re-answer one disagreeing pair and sign a ruling tells you which twin it agrees with, and when nobody can rule, the pair is left unruled rather than counted against anyone.

What must hold
  • Verify before you show.
  • A judgment is never rounded into evidence.
  • History is counts anyone can recompute, never a score.

1What it is

Use-case evidence is what you add on top of the plain record when your use case asks a question the record cannot answer by itself; for inference served on strangers' machines that question is whether a node served the model its record names.

Sending some requests to two nodes and comparing the answers gives you a rate, how often a pairing's answers differed, which tells you something is off without telling you who.

Adjudication adds a third node that re-answers one differing pair and signs a ruling naming the twin it did not agree with; where no node can do that, the pair reads “not adjudicated” and counts against no one.

2Design choices

Chosen: a pair exists only when a client sends the same x-mesh-twin-bracket value on two requests; the host copies it into twin_bracket_id and never sends a second request itself.
Rejected: the host duplicating a share of requests at a configured rate, or pairs guessed from timing or content. No such rate setting exists in the host or in the plugin; the cost knob is how many pairs a client marks, plus the operator's referee switch. (mesh-llm docs/plugins/openai-exchange-lifecycle.md, “Client-marked pairs”; PR 2144; capsules docs/TWIN-REFEREE-SELECTION.md §1, §4)
Chosen: the header is stripped before a request is forwarded, so a serving node cannot know its answer is half of a pair.
Rejected: forwarding it, which would tell a serving node which of its answers are being compared. (mesh-llm PR 2144, forwarded_request.rs; test added in PR 2300)
Chosen: compare only pairs answered at temperature 0, on the same model hash and the same weights digest, by exact words; any difference counts.
Rejected: comparing sampled answers, which differ honestly, and a similarity threshold. A pair outside these rules reads “not comparable” with why. (capsules crates/evidence-plugin/src/referee/request.rs, before_asking; crates/evidence-plugin/src/referee/verdict.rs)
Chosen: without a referee a difference is inconclusive; only a referee's re-answer names a twin, and only the twin it did not agree with.
Rejected: the requesting node deciding, or treating a difference as evidence against either side. (capsules crates/evidence-plugin/src/referee/verdict.rs, referee_verdict; vectors/parity/referee/intended_differences.json, “only the referee signs”)
Chosen: no eligible referee, a referee that cannot sign, or one that does not answer: “not adjudicated” with the reason, counting against neither twin; at most one call per pair, never retried on its own.
Rejected: reading a missing ruling as a contradiction, and retrying other referees until one rules. (capsules docs/TWIN-REFEREE-SELECTION.md §4; crates/evidence-plugin/src/referee/request.rs, NO_ELIGIBLE_IS_RETRIED_AUTOMATICALLY = false)
Chosen: eligibility is a set of yes/no rules (same model and weights, neither twin, announced key, not blocked, no contradiction for that model in the last referee_bar_days); the pick is random within a tier, and the tier is sealed in the verdict.
Rejected: ordering nodes by merit or blending anything into one number; verdicts are counted per peer; the counts stay on this node and are never sent to anyone. (capsules docs/TWIN-REFEREE-SELECTION.md §2, §3, §5; crates/evidence-plugin/src/verdict_counts.rs)
Chosen: the referee is off by default; the operator turns it on (adjudicate_differing_twins).
Rejected: on by default: asking a referee sends the twins' request, including the prompt, to a third node. (capsules docs/SHARING-POLICY.md; CHANGELOG.md 0.1.3)
Chosen: the record keeps a slot for hardware evidence and writes it empty when no quote was taken.
Rejected: filling it from what a node says about itself; a producer must not record an assurance mode it did not achieve, and the same rule applies here: no quote, no claim. (capsules crates/evidence-plugin/src/producer/capsule.rs, tee_attestation; draft-mih-scitt-agent-action-capsule-05 §5.4)

3What it shows / what it does not

Shows

  • Sampling only: for pairs a client marked, whether the two sealed answers were byte-identical (their answer digests); over many pairs, how often a pairing differed (“Twin pairs: N · answers differed: M”). Sampled answers count as differing too.
  • With a referee: a signed ruling on one pair: which twin the referee's re-answer agreed with at the earliest differing word, with the other named contradicted:<node>.
  • What the ruling covers: both halves' record ids, the request digest, the weights digest and the referee's own answer digest, all under the referee's signature, which a holder can verify against the referee's key.
  • For a pair with no ruling, why: off, not marked, answers agree, not comparable (with why), no eligible referee, referee cannot sign, referee did not answer.

Does not show

  • Sampling only: which twin was wrong, or that either was. A difference counts against no one.
  • Which model ran. The matching weights are each node's own claim, and twins serving the same wrong file corroborate each other.
  • A node's future answers. A verdict is a ruling on one pair.
  • Honesty across different hardware: exact replay can differ on different silicon for reasons unrelated to honesty, so such a mismatch is grounds to investigate, not a ruling.
  • That the referee is independent of either twin; that is a claim about who runs it.
  • Anything about a pair no client marked.
  • Hardware evidence: at v0.1.4 no hardware quote is taken.

"operator_off_calls_nothing_and_says_so": [{"counts_against":null,"referee_calls":0,"row":{"reason":"off","state":"not_adjudicated"}}]
"differing_pair_triggers_one_call": [{"counts_against":"node-b","referee_calls":1,"row":{"referee":"node-c","state":"adjudicated","tier":1,"verdict":"contradicted:node-b"}}]

FieldTypeMeaning
twin_bracket_idstringThe value the client sent in x-mesh-twin-bracket. Without one, nothing is compared and nobody is asked.
request_digesthexDigest of the request both twins answered; with the bracket id and the two node ids it is the pair's key, so a re-sealed half is the same pair.
capsule_idhexEach twin's own signed record of its half.
node_idstringThe node that served the half (placeholder ids in the corpus).
temperaturenumberAbove 0 means sampled: the pair reads “not comparable”, because sampled.
model_hash / weights_digesthexWhat each half's record says it served. Both must be named and equal, or the pair is not comparable. Self-report.
textstringThe answer. A node holds it only when the client supplies it and its digest is the record's response_digest.
statestringadjudicated or not_adjudicated.
reasonstringWhy a pair has no ruling: off, no_eligible_referee, and the other reasons listed above.
verdictstringThe referee's ruling: contradicted: plus the twin it did not agree with, or inconclusive, or not_comparable.
referee / tierstring / intWho was asked, and from which tier: 1 has a corroborated verdict for the model on this node's chain, 2 has none yet.
referee_callsintCalls this attempt made: 0 or 1.
counts_againststring / nullThe node the row's contradiction counts against; null for every unruled pair.

The corpus states these answers from the rules; the plugin's tests run them. Two of the three cases leave the setting unset, which the test harness reads as on; a running node reads an unset adjudicate_differing_twins as off. The signed verdict record a referee seals, with its own fields, is crates/evidence-plugin/tests/fixtures/referee-verdict.json at the same tag (the fixture predates -05 and carries spec_version -04; the plugin seals -05).

6Specs

  • Internet-Draft draft-mih-scitt-agent-action-capsule-05 — the record each twin and the referee seals; §5.4, a producer must not record an assurance mode it did not achieve.
  • Internet-Draft draft-mih-agent-evidence-layer-00 — §4.1, the adjudication epistemic type; §5, the adjudicates link a verdict carries.
  • Internet-Draft draft-mih-agent-bilateral-attestation-02 — both sides of an exchange each keeping a signed record: the halves a comparison reads.
  • RFC RFC 9052 — COSE: the COSE_Sign1 signature on each half and on the verdict.
  • RFC RFC 8785 — JSON Canonicalization Scheme: the bytes every digest covers.
  • Code Mesh-LLM/capsules v0.1.4 — the comparison, the referee, the verdict record and the rule corpus.
  • Code Mesh-LLM/mesh-llm#2144 — the header copied into twin_bracket_id and stripped before forwarding (merged, in v0.78.1).
  • Code Mesh-LLM/mesh-llm#2300 — the twin_bracket capability (merged, not yet released).

7What you need before the next step

  • A host seam that lets a client mark two requests as one pair and hands the mark to your plugin on both exchanges, without telling the serving nodes.
  • Both halves of each pair held on the comparing node (the counterparties' signed records, pushed or fetched), and a way to get the texts there that you can check against the records' digests.
  • An operator switch for the referee, off by default, because asking one sends the prompt to a third node.
  • Yes/no eligibility rules, one call per pair, and a “not adjudicated” row with its reason for every case that has no ruling.
  • A record slot for hardware evidence, written empty until you take a quote.
