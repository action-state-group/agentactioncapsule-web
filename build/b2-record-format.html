The record format

Before you keep a book of records, decide what one record carries: digests of what went in and what came out, the effect it names and who vouches for it, a nonce the store draws itself, and the key that signs the record's identity.

1What it is

The record format is the choice of what one record commits to for one action: which facts go in as digests, which go in as plain values, and which never go in at all.

For a model exchange, the Agent Action Capsule Internet-Draft gives the effect type inference_completion, which binds the request and the completion by digest, and a COSE_Sign1 Producer Envelope that signs the record's identity under a key named in its kid.

Mesh-LLM's capsules plugin (release v0.1.4) is the worked example: it fills those fields from the host's exchange event, adds a store nonce, a join nonce and the serving facts, and leaves its hardware-evidence slot empty.

2Design choices

Chosen: commit the request and the completion by digest, SHA-256 over the JCS form of each body, with any floats first written as decimal strings (Draft -05 §2); the bodies stay with the node that saw them.
Rejected: carrying content. A sealed record cannot be retracted, so content that must be checkable later but not disclosed now goes in as a digest only; and a user or session identifier is excluded, not digested, because a digest of a low-entropy value can be reversed by guessing. (Draft -05 §2, §5, §14, §14.1)
Chosen: name the effect. For inference_completion, request_digest covers the request body as received at the serving boundary and response_digest the completion body as returned; status: "confirmed" requires the response digest.
Rejected: a status label with nothing bound to it. When the host forwards no response digest, v0.1.4 seals status: "dispatched" with no response digest rather than claim a completion. (Draft -05 §5.3; capsules crates/evidence-plugin/src/capsule_emit.rs)
Chosen: say who vouches for the effect in effect_attestation: host_served_observed when the plugin only saw the host's report of the exchange, gate_executed when the plugin admitted and served the request itself.
Rejected: grading a host's report as a direct observation. host_served_observed grades equal to runtime_claimed, below gate_executed. (Draft -05 §5.3; both seal paths in capsule_emit.rs)
Chosen: sign the identity, not the JSON: a COSE_Sign1 Producer Envelope over the 32 raw bytes of capsule_id, protected header exactly alg EdDSA, content type application/agent-action-capsule-id and kid (the raw Ed25519 public key); unprotected header empty.
Rejected: making the signature part of the identity, and putting anything in the unprotected header: a witness receipt belongs to a separate registration statement, not the Producer Envelope. Whether the key is authorized for the operator is the caller's policy. (Draft -05 §3.1, §3.2, §3.3)
Chosen: every record carries store_nonce, 256 bits the store draws from a secure random source for that record alone, committed into capsule_id.
Rejected: relying on the client's nonce, a time or a sequence number. Another party knows or can guess those, so the sibling digests in an inclusion proof could be checked against guessed content. (draft-mih-agent-evidence-layer-00 §12.1; capsule-emit 0.0.6 rust/capsule-emit/src/capsule.rs @ 44ad8bd528b029c1abff1937f700423f94e1d6db, tag crates/capsule-emit-v0.0.6)
Chosen: cite hardware evidence by digest: a references entry {type, digest_alg, digest} with citation_purpose: "ran_under". The cited record's grade covers only what that record measured.
Rejected: citing by name or URL, which can later resolve to different bytes; and letting a hardware-measured value lift a self-reported claim inside the same cited record. (Draft -05 §5.5.5; the citation_purpose table and grade rule are printed under §5.5.6)
Chosen: name model facts for what they are: model_name_digest is a hash of the model's name; weights_digest, the SHA-256 of the served file's bytes, is sealed only when the host reports it, with scope: "file". The serving host's name is left out unless the operator opts in.
Rejected: a name hash presented as a model identity, and a default value for any fact the host did not report. (capsules crates/evidence-plugin/src/producer/capsule.rs)

3What it shows / what it does not

Shows

  • That the holder of the key in kid signed this capsule_id, and, once the verifier recomputes the id, that the record's bytes are the ones signed.
  • To anyone who holds the request or completion body: whether it is the body this record committed to.
  • That a confirmed effect carries a digest of the response that was observed, and which grade of voucher the producer states.
  • When the client supplied a nonce or the host forwarded one: which records are the two halves of one exchange, through the shared client_nonce. The marker host-served-no-nonce joins nothing.
  • With store_nonce in every record: the siblings in an inclusion proof cannot be confirmed by guessing a record's content.

Does not show

  • What the request or the completion said.
  • Who holds the key in the real world, or that it was authorized to sign for the operator (Draft -05 §3.2).
  • That the named model ran. model_name_digest hashes a name; weights_digest is the host's report of the file it opened.
  • Anything rooted in hardware. In v0.1.4 the tee_attestation slot is always empty, and binary_attestation is the plugin measuring its own executable (self- or OS-measured); on the host-served path that is not the runtime that served the model.
  • That every exchange was recorded: a record shows this exchange was recorded, not that none was left out.
  • Privacy from client_nonce: it is a join key both sides know, not a secret.

6Specs

  • Internet-Draft draft-mih-scitt-agent-action-capsule-05 — the record, its identity, the effect record, the Producer Envelope, and references with citation_purpose.
  • Internet-Draft draft-mih-sokolov-scitt-payload-binding-05 — the typed digest reference {type, digest_alg, digest} a references entry uses.
  • Internet-Draft draft-mih-agent-evidence-layer-00 — why every record carries a store-drawn random value (“What a Checkpoint Reveals”).
  • RFC RFC 8785 — JSON Canonicalization Scheme: the bytes every digest and capsule_id covers.
  • RFC RFC 9052 — COSE: the COSE_Sign1 Producer Envelope.
  • RFC RFC 8949 — CBOR: the envelope's encoding (tag 18).
  • RFC RFC 9943 — SCITT architecture: the separate registration statement for a capsule_id.
  • RFC RFC 9942 — COSE Receipts: what that registration returns.
  • Code action-state-group/agent-action-capsule — draft source and conformance vectors.
  • Code Mesh-LLM/capsules v0.1.4 — the worked example's producer.
  • Code action-state-group/capsule-emit — the sealing library the plugin links (crate 0.0.6, tag crates/capsule-emit-v0.0.6 @ 44ad8bd528b029c1abff1937f700423f94e1d6db).

7What you need before the next step

  • A field list for each kind of record: what goes in as a digest, what goes in clear, and what never goes in (user and session identifiers, secrets).
  • An effect type and an honest effect_attestation value for each kind of action your host performs.
  • A signing key per producer (Ed25519), its public key as kid, and a way for peers to learn it.
  • A store-drawn random value in every record, separate from any nonce a client or peer supplies.
  • A JCS implementation that passes the format's canonical vectors, so your capsule_id recomputes anywhere.
  • A decision on where hardware evidence would be cited (ran_under), even before you have any.
