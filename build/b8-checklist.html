The builder's checklist

The seven steps in the order they were built for Mesh-LLM, each with what you need, where it lives today, and how far along it is, checked against the repositories on 2026-10-19.

1What it is

An evidence layer is built bottom up: the host has to expose a few seams first (an exchange event before any record can be sealed, the rest before records can be checked and acted on), then come the record format, the local book, the use-case evidence, and only then the parts that make it portable.

Each step below names what a builder needs from their own host or code, and where the Mesh-LLM worked example keeps it today: a crate, a repository, or an Internet-Draft.

Status is what the code shows at a named commit or what a pull request's state shows today, not what a slide or plan says.

2Design choices

Chosen: ask the host for small generic seams (events, a plugin key, a capability flag, a page, a stop-routing request) and keep evidence in one plugin.
Rejected: patching or forking the host, and operators copying each peer's key by hand, which “does not scale past a few nodes”. (mesh-llm PR 2299; the plugin depends on mesh-llm-plugin = "0.78", capsules crates/evidence-plugin/Cargo.toml)
Chosen: every record, its ledger, checkpoints and checks come from published libraries, pinned by version.
Rejected: a plugin-private record format, or library code copied into the plugin. (capsules crates/evidence-plugin/Cargo.toml: capsule-emit 0.0.6, checkpointed-local-log 0.2.1, capsule-emit-evidence-request =0.0.3)
Chosen: the local book first, with nothing leaving the node by default; sharing is a later, explicit switch.
Rejected: sharing on by default. (capsules CHANGELOG.md 0.1.3: record push, verdict delivery and the referee are off by default; checkpoint_cadence.rs: checkpointing is on by default, local only, no witness)
Chosen: use-case evidence that rules on one pair (a referee's signed verdict), only for a pair a client marked.
Rejected: the host inventing pairs: a referee is asked only for a pair a client marked (capsules docs/TWIN-REFEREE-SELECTION.md §1). Also rejected: sampling alone, which gives a rate, not a ruling on one exchange (the reasoning on b4).
Chosen: portability through open Internet-Drafts, vectors and libraries any host can link.
Rejected: a check that needs an account or a running service; a bundle from an evidencebook book on the CLL substrate “verifies, interval and all, with the neutral Evidence Bundle verifier alone”. (evidencebook README.md)

3What it shows / what it does not

Shows

  • The order of work that produced a running example, and what each step depends on.
  • Where each piece lives today, by crate, repository and Internet-Draft, so a builder can link the same libraries.
  • Each status with the commit, tag or pull request it was read from on 2026-10-19.

Does not show

  • That any step is finished for every host: these rows are the Mesh-LLM example.
  • That a released plugin is installed or switched on anywhere; “live” here means in a published release anyone can install.
  • Status after 2026-10-19: open pull requests may have moved since.
  • Whether any record's content is true: each step records and checks; none judges an answer.

7Back to the start

That is the whole path. To build your own, take the steps in this order and do not skip the seams: every later row depends on what the host exposes.
