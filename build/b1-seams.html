The seams the host exposes

Seam ① Record. Build: the host hooks a recorder needs: an exchange event naming both sides, a bound plugin key, capability flags, a page, stop routing. Conform to: draft-mih-scitt-agent-action-capsule-05 for the record those events feed, draft-mih-agent-bilateral-attestation-02 for the two sides.

Before an evidence plugin can do its job, the host your agents run on has to hand it a few small, generic things: an event per exchange that names both sides, a way to vouch for the plugin's signing key, flags saying what it supports, a place on screen, and a way to stop routing to a peer.

What must hold
  • Verify before you show.
  • A judgment is never rounded into evidence.
  • History is counts anyone can recompute, never a score.

1What it is

A seam is a small, generic hook the host exposes so that a separate plugin, not the host itself, can keep evidence about what the host did.

An evidence plugin needs the first of them to seal a single record: an event per exchange that names both nodes. The other four let it check peers' records (a key its peers can check), tell what the host supports (flags), show records (a page and slots), and act on what it finds (stop routing to a peer).

If you build agents on someone else's runtime, these are the things to ask that runtime's maintainers for; Mesh-LLM is the worked example, where each seam landed upstream through its own pull requests and the evidence code stayed outside core.

2Design choices

Chosen: the exchange event carries digests and node ids, not the prompt or answer; the default plugin's entry does not allow the exchange hook that can see text.
Rejected: handing an audit plugin the conversation. (mesh-llm mesh/docs/plugins/README.md “Default Plugins”; PR 1841)
Chosen: requested_by_node_id comes from the authenticated mesh connection the request arrived on, so a client cannot set it; a routing node names only the peer it saw deliver.
Rejected: a header or body field the requester fills in, and naming hardware or model details for a peer the node never touched. (PR 2138)
Chosen: the node key signs only a binding ("mesh-llm-plugin-key-v1:" ‖ node id ‖ plugin name ‖ key ‖ algorithm); the plugin signs its own records; keys are not relayed.
Rejected: operators copying each peer's key by hand, and the node key signing plugin data. (PR 2299)
Chosen: the host advertises each seam as a named capability (plugin_keys.v1, peer_blocks.v1, capabilities.twin_bracket); a plugin call against a host without plugin_keys.v1 or peer_blocks.v1 fails at once.
Rejected: inferring support from an absent field: an exchange without twin_bracket_id may simply not have been marked. (PR 2300; README.md “Plugin Keys”, “Peer Routing Blocks”)
Chosen: exactly two named slots (chat_message, logs_request) where the host passes ids only; a page may ask for a primary tab and the operator decides.
Rejected: a general extension-point system, and a plugin promoting itself into the main navigation. (PRs 2140, 2130)
Chosen: stop routing is local to one node, names who asked (operator or plugin:<id>), and a plugin may request it only if the operator set allow_peer_blocks for it.
Rejected: a shared blocklist, which would let any peer get an honest one excluded with made-up reports, and any ranking kept by the host. (PR 2142)
Chosen: evidence ships as one plugin, pinned by version and per-platform SHA-256 on the host's default list, which the operator can turn off.
Rejected: compiling evidence into core, and installing a default by download (PR 2337 replaced the download-on-first-run install of PR 2188).

3What it shows / what it does not

Shows

  • Which node asked and which node served one exchange, as each node observed it, with digests of the request and response, so the two sides' records of one exchange can be matched.
  • That a peer's node key vouched for a given plugin key (where the host lists it).
  • Whether a host supports a seam at all, from its own capability flags.
  • Who stopped routing to a peer, and why, as a change published to local plugins.

Does not show

  • That the serving node ran the model it claims: node ids and digests are the host's observations, used to pair records, not evidence of what ran.
  • Anything about honest serving from the key binding: it says only that the node key vouched for the plugin key (PR 2299).
  • Keys of peers you are not directly connected to: plugin keys are not relayed. A stable identity for client-only nodes is not addressed (PR 2299).
  • Anything to other nodes from a block: it stays on this node and warns no one.
  • Any record at all: the seams carry events; sealing them is the plugin's job (next page).

6Specs

  • Internet-Draft draft-mih-scitt-agent-action-capsule-05 — the record a plugin seals from each exchange event (next page).
  • Internet-Draft draft-mih-agent-bilateral-attestation-02 — two parties' records of one exchange; why the event must name both nodes.
  • RFC RFC 8785 — JSON Canonicalization Scheme: the form under request_digest and response_digest.
  • Code Mesh-LLM/mesh-llm plugins README — “Plugin Keys”, “Peer Routing Blocks”, “Default Plugins”, the web UI slots.
  • Code openai-exchange-lifecycle.md — the exchange event contract, including “Client-marked pairs”.

7What you need before the next step

Write down the seams you will ask your own host for. A builder on any agent runtime can use this list:

  • An event per exchange (or per tool call, per task) with a stable id, digests of what went in and out, and the ids of both parties, taken from an authenticated channel.
  • A way for your plugin's signing key to be vouched for by the host's own identity, and seen by peers.
  • Capability flags for each seam, so absence of data is never read as absence of support.
  • A page and a slot or two next to the host's own rows, where the host passes ids only.
  • A local, operator-controlled “stop sending work to this party” that a plugin can request only with the operator's opt-in.
  • A way to ship as one removable, pinned plugin rather than as core code.

With the event in hand, the next question is what a record of it should carry.
