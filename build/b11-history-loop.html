History back into the loop

Seam ⑤ View, back into ①. Build: History as a read over sealed records that shapes the next act. Conform to: draft-mih-agent-evidence-request-00 (history_card/1).

The loop closes when what was recorded and judged shapes the next act. In Mesh-LLM a node's own count of referee verdicts about a peer can stop it routing to that peer; in a personal agent the person hands one recipient a History of selected deals. Both are reads over sealed records, and neither is a score.

What must hold
  • Verify before you show.
  • A judgment is never rounded into evidence.
  • History is counts recomputed from sealed records, never a score.
The general rule. History is a derived read over records already sealed, never a new fact. It reports counts in their own units, says what it does not establish, and is never folded into one number about a party. Who can recompute it differs: a personal History is recomputed by anyone holding the replies; a Mesh-LLM node's verdict counts are its own, because they also read two unsealed local files (which pairs this node asked a referee about, and which verdicts a rule block already used).

1What it is

History is the last step of the loop: a read over records that were already sealed and judged, used to shape what happens next.

In Mesh-LLM a node counts the referee-signed verdicts about each peer from its own chain, and an operator can opt in to a rule that asks the host to stop routing to a peer after enough contradictions; for a personal agent, the person gives one recipient a History of selected deals, counted by state.

In both cases the read is computed from records already sealed, it reports counts with what they do not establish, and no step turns them into a score.

2Design choices

Chosen: four separate counts per peer (corroborated, contradicted, inconclusive, not comparable), each a list of verdict ids that can be opened.
Rejected: a computed figure about a peer, or the counts blended into one number. (capsules v0.1.4 crates/evidence-plugin/src/verdict_counts.rs; docs/TWIN-REFEREE-SELECTION.md §5: “Nothing is ordered by merit, weighted or combined into a number”)
Chosen: a received verdict counts only if this node itself asked that referee about that exact pair of halves, and once per referee and pair.
Rejected: counting any validly signed verdict. A signature says who signed, not that anyone asked: a peer with an announced key could mint verdicts about another peer at will. (verdict_counts.rs, gate 2)
Chosen: the counts and every block stay on this node; a block is never gossiped or shared.
Rejected: a shared list, which “would let any peer get an honest one excluded with made-up reports”. (mesh-llm network/peer_blocks.rs module doc, v0.78.1)
Chosen: the rule is off unless the operator sets N, one referee contributes at most N − 1 contradictions, and the plugin only asks; the host refuses unless its operator set allow_peer_blocks = true for that plugin.
Rejected: a plugin that routes, or that blocks through the operator's own API. (routing_rule.rs; capsules CHANGELOG 0.1.3; mesh-llm docs/plugins/README.md “Peer Routing Blocks”)
Chosen: the record of a block names the peer only by sha256(salt || peer id), and cites the verdicts that met the rule the same way; the salt stays on this node (for a rule block the plugin draws it and keeps it in its local routing-rule-cited.jsonl).
Rejected: naming the peer in clear. A range answer returns whole records to any asker, so a clear name would tell everyone who was blocked. (producer/capsule.rs seal_local_routing_choice)
Chosen: verdicts that met the rule never count toward it again, so undoing a block holds until new contradictions arrive.
Rejected: re-firing on the same verdicts the moment an operator lifts a block. (routing_rule.rs, routing-rule-cited.jsonl)
Chosen: for a personal agent, a History is a recipient-specific disclosure counted in selected deals, with “outcomes not established” shown before any count.
Rejected: any figure that adds deals to records, combines across deals, holders or counterparties, or orders or grades them. (spec/personal-agent-history-profile-v0.md §5, §6.3, §9 “No ordering”)

3What it shows / what it does not

Shows

  • How many referee-signed verdicts this node asked for and received about a peer, in each of four outcomes, each verdict openable by id.
  • That a block was made, when, for how long, and, for a rule block, which rule (N, D) and which verdicts met it, by commitment.
  • For a personal History: which deals the holder selected for this recipient, and how many have a recorded failed step, completed steps only, or no step.
  • For a personal History, counts any holder of the replies recomputes; for a mesh node, counts it recomputes from its own chain and its own local list of referee requests.

Does not show

  • Anything about a peer's future answers: a verdict is a ruling on one pair of answers (TWIN-REFEREE-SELECTION §5).
  • What any other node counts or blocks: counts and blocks are local and never shared.
  • That a person made a block: the record says human_disposed: false, since a local API call does not show who made it.
  • For a personal History at the Basic level: any outcome, or that the selection is all of the holder's deals. Outcome claims, each with one source label, are the profile's Outcome level (designed).
  • That another node holding the same chain would count the same: gate 2 reads this node's own unsealed list of the referee requests it sent.
  • A ranking, a grade, or a single number about a party.

7What you need to close the loop

  • A history computed only from your own sealed records, with gates on which judgments count (verified, asked for by you, once each).
  • Counts kept in their own units, each one openable down to the records behind it, and never combined into a number about a party.
  • A host seam to act on it (here, stop routing) that the operator opts into, that stays local, and that the operator can undo.
  • A sealed record of each such act, naming the counterparty only by a salted commitment if your records can be served to others.
  • Then back to the start: the next act is recorded, judged, reported and read again. The contents page shows the whole loop.
