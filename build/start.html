Start

Five basic things

Seams ① Record to ⑤ View. Build: one record carried through all five seams, by hand, with the open tools. Conform to: the Internet-Draft or specification each step names.

An afternoon's worth of first steps for a builder who wants an evidence layer of their own. Seal a record, keep it in a log, check it offline, hand it to someone who asks, then seal a Result and show it. The first three have their own pages already; this page links them and writes out the last two. The rest of the build pages explain each seam in depth.

What must hold
  • Verify before you show.
  • A judgment is never rounded into evidence.
  • History is counts anyone can recompute, never a score.

Every command below is copied from the README of the tool that runs it, at the commit named under it. capsulectl is published as release candidates (latest v0.1.0-rc20, 2026-10-22); capsule-emit, checkpointed-local-log and agent-action-capsule install from PyPI.

1Seal a record

Seam
① Record
Spec
draft-mih-scitt-agent-action-capsule-05
Tool
capsule-emit (one seal() call), or capsulectl seal from capsule-cli

One call turns an action your agent took into a signed record of digests: who acted, what was done, and digests of the input and output. You keep the raw values; the record carries only their digests.

pip install capsule-emit

From the capsule-emit README at 69febf023368769d82f9e1985dbd8049a8aadb8c.

2Keep it in a checkpointed log

Seam
① Record
Spec
draft-mih-scitt-checkpointed-local-log-02 (CLL)
Tool
checkpointed-local-log, or capsulectl cll

Append the record to a log on your own disk and sign a small checkpoint over it. The checkpoint lets anyone check that a record is in the log (an inclusion proof) and that the log only grew (a consistency proof). Sending the checkpoint to a public witness is optional; only a digest and a timestamp leave.

pip install checkpointed-local-log

From the checkpointed-local-log README at 32ce9f3f901ea85c80a4b42b6fd3ee007fdda2c0.

capsulectl cll append --profile demo --capsule artifact.json
capsulectl cll checkpoint create --profile demo

3Verify it offline

Seam
① Record to ④ Result
Spec
draft-mih-scitt-agent-action-capsule-05 and its conformance vectors
Tool
the reference verifier in agent-action-capsule; scitt-cose for COSE Receipts

Check the record from its bytes alone: no account, no network, no clock. A record changed after sealing no longer matches its own capsule_id, and the verifier says so.

git clone https://github.com/action-state-group/agent-action-capsule
cd agent-action-capsule
pip install -e python            # or: pip install agent-action-capsule

# a known-good conformance vector  ->  ok: True (one info finding: chain checks need a store)
agent-action-capsule verify vectors/capsule/pos-v4-jcs-chain-committed/input.json

# a tampered capsule               ->  ok: False, capsule_id_mismatch
agent-action-capsule verify vectors/capsule/neg-v4-chain-tampered/input.json

From the agent-action-capsule README at db9de0f0d2b78efdd096dc4016a63785cca96601.

4Answer an evidence request with a bundle

Seam
① Record to ⑤ View
Spec
draft-mih-agent-evidence-request-00 (the request) and draft-mih-zhang-agent-disclosure-bundle-00 (the Evidence Bundle, evidence-bundle/v2)
Tool
capsulectl disclose and capsulectl verify --bundle from capsule-cli

Someone asks you for evidence of an action. Under the Evidence Request draft the answer is one of three outcomes: the artifact, a signed refusal, or a recorded absence. When you answer with the artifact, you hand over one file: an Evidence Bundle.

What the requester gets: the records the answer cites, their signatures, a signed checkpoint, and one inclusion proof per record, so they can check the records are in your log under that checkpoint. With --payloads selected, only the payloads you choose travel with it.

What stays withheld: any payload you leave out, or name with --suppress agent_input or --suppress agent_output. The record still commits to it by digest, so the requester can see that it exists and that you did not show it, and can check it later if you do.

capsulectl disclose --profile NAME --root CAPSULE_ID --out BUNDLE.json [--html PAGE.html] [--payloads all|selected] [--suppress agent_input|agent_output] [--producer-key HEX]
capsulectl verify --bundle BUNDLE.json [--witness-directory WITNESSES.json]

From the capsule-cli README, Commands at f8aefe98445eaa9217e24627e255681c3857ae3d. The README's worked example runs both end to end.

verify --bundle says VALID (exit 0), INVALID (exit 1) when a record or payload changed after sealing, or INCOMPLETE (exit 3) naming what the bundle does not show. A VALID bundle means the signatures verify under the keys the bundle carries; whether those are keys the requester trusts is a separate check, against the producer's public key obtained some other way.

The request side, its outcomes and the signed refusal have conformance vectors in agent-action-capsule/vectors/evidence-request. Read more: b5 · Making it portable, b7 · Agent work for someone else.

5Seal a Result and show it planned

Seam
④ Result to ⑤ View
Spec
Evidence Result v0 (schema evidence-result-v0.json) and the Presentation contract v0
Tool
capsulectl result build from capsule-cli

A Result says, per requirement, what was judged and with what assurance, and cites the records each claim rests on. Sealing it makes it a record like any other, so it can be the root of a bundle. A page is then drawn only from a bundle that has verified: the page cannot change the verdict, and wording changes never move an evidence id.

capsulectl result build --profile NAME --result RESULT.json [--out CANONICAL.json] [--contract REF] [--capsule-out RECORD.json]

From the capsule-cli README, Commands at f8aefe98445eaa9217e24627e255681c3857ae3d.

Status. This step is marked planned. result build needs no plugin and is in the capsulectl release candidates from v0.1.0-rc19; it validates against the evidence-result-v0 schema and refuses a headline value that does not recompute from the claims. The page half is defined by the Presentation contract, which is a v0 design specification. Until the whole step runs from a neutral release on its own, read this one as the shape of the step, not a finished path.
