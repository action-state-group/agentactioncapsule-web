The record, both directions

A single-party capsule records what one agent did. When two agents transact across organizational boundaries, each is bound to its part — and each holds verifiable proof of the other's. That is a bilateral attestation.

The problem: my log vs your log

When two parties to a transaction each keep their own log, neither log is independently auditable by a third party who trusts neither side. Each operator can edit their own log. Each can claim a different version of events. The result: disputes resolve on assertion, not evidence.

A bilateral attestation changes this. Each party's action is sealed and anchored; each holds a cryptographic receipt of the other's. A third party who trusts neither can verify both independently.

The four-move handshake

At neutral altitude, the exchange follows four moves:

  1. Request attestation. The requesting party seals a signed statement over the requested action — committing to what it is asking, content-blind (by digest). The requester is bound to what it asked.
  2. Constraint evaluation at the effect boundary. The responding party evaluates whether the action falls within its declared constraints before executing. This is the gate moment — not a log entry, but the decision.
  3. Action attestation. The responding party seals a signed statement over the action it actually took — with a disposition drawn from the shared vocabulary (executed, blocked, denied, timeout, errored, deferred, expired, escalated). Both parties are now bound to their respective statements.
  4. Acknowledgment. The requesting party seals a receipt-of-action — confirming it received the outcome. The chain is closed.

Each move produces a capsule. Each capsule is independently anchored. Any third party can verify any move without the cooperation of either party.

Refusal is evidence too

A key design property: refusal is recorded with the same fidelity as performance. If the responding party declines, the disposition is blocked, denied, or errored — sealed and anchored. This cuts both ways: the performer holds provable evidence of a lawful decline; the requester holds provable evidence that the action was asked for and declined. Neither party can later claim otherwise.

Disposition vocabulary

DispositionMeaning
executedAction was performed as requested.
blockedAction was received but stopped before execution — a constraint prevented it.
deniedAction was refused outright — the responding party declined to act.
timeoutAction did not complete within the agreed window.
erroredExecution was attempted but failed with an error.
deferredAction is pending a future event or approval before it can proceed.
expiredThe request or execution window elapsed before the action completed.
escalatedThe action was referred to a higher authority or out-of-band process.

This vocabulary is shared with the base Agent Action Capsule profile, so bilateral records compose directly with single-party records across the same transparency log.

Graceful degradation

Not every peer will implement bilateral attestation. When one side is bilateral-capable and the other is not, the capable side records a reduced-assurance marker — acknowledging that the other's statement was not verifiably sealed. The record is never silent about this: a missing counter-attestation is surfaced, not hidden.

Roots of trust — generic

This mechanism does not nominate a root of trust. Any trust anchor that allows both parties to verify each other's signing keys is sufficient: a shared certificate authority, a federation, a public trust list, or a mutually agreed registry. The four-move protocol is the same regardless of how keys are established. Implementors choose the root of trust appropriate to their context.

Relationship to the base capsule

A bilateral attestation is an extension of the single-party Agent Action Capsule profile — it reuses the same COSE envelope, the same chain.relation reference-by-digest mechanism, and the same disposition vocabulary. The responding party's action capsule is the WHAT leg of the cross-party accountability picture; the request capsule is its bilateral counterpart. Both anchor to the same transparency log; the receipt chain links them.

See how it composes for the single-party composition model that this extends.
