You've reached a witness

You probably followed a link from a checkpoint, a receipt, or a post about one. Here's the whole idea in about five minutes: what a checkpoint is, what a witness does and does not show, and how to check any of it yourself — without asking you to trust us.

What is a checkpoint?

A checkpoint is one signed value — a 32-byte root, signed: about 300–500 bytes on the wire — that commits an entire log's history to date. Whoever holds the log can recompute that value from every entry they've recorded; if even one byte of one past entry changed, the checkpoint would no longer match. It's witnessed when an independent party co-signs it, which is what turns "trust me, my log is complete" into something a stranger — you — can check without trusting anyone.

What this witness shows — and what it never does

A witness is infrastructure, not a verdict. It commits to three things, checkable from the bytes alone:

  • Existence — the record was in the log at a point in time.
  • Order — where it fell relative to everything else.
  • Completeness — nothing between two checkpoints was quietly dropped or rewritten.

It never says anything about whether the content was true. These are the claims this project will not round up, anywhere — the same wording an auditor reading the spec would use:

  • A witnessed record is not a true record. The stamp attests existence/order/completeness, never accuracy.
  • A derived verdict is not an adjudicated one. verify never grades up — it never reports more assurance than the bytes support: absence ≠ forgery, unsigned ≠ invalid.
  • Coverage is the range, not the population.
  • Registration ≠ Receipt ≠ Witnessing. Registration is the act, a Receipt is what the service returns, witnessing is a party co-signing the checkpoint so the log can't equivocate.

Word-for-word, in three registers — dev, auditor, spec — on the translation page.

The grade you'll see

Not every checkpoint this witness shows you was built the same way, and the label tells you which:

GradeWhat it means
mmr-verifiedThis witness holds the underlying log entries itself and independently recomputed the checkpoint from them. It rebuilt the tree; the root matches.
countersigned-observedThe checkpoint was minted by a different log this witness doesn't hold the entries for. This witness checked the signature and co-signed it — so a stranger can't be shown two different versions — but it did not rebuild the tree behind it.

These two are never presented as one guarantee. A countersigned-observed checkpoint is not proof this witness recomputed anything; it's proof the checkpoint you're looking at is the one everyone else sees too.

Run your own

This witness runs on open-source infrastructure — auditable in full, Apache-2.0. You don't have to take this instance's word for anything you can check yourself, and you don't have to use this instance at all: run your own witness in the region you choose, or self-host it inside your own network where nothing but a digest ever leaves. See witness anywhere for the options.

It is built to have no single point of trust, including whoever runs this instance. Other operators running the same log side by side is the design goal: more independent witnesses is strictly better for everyone checking a record, including the operators of any one of them.

What is a Capsule?
Agent Action Capsule

An open, individual profile (an IETF Internet-Draft; not WG-adopted) built on the SCITT Architecture (RFC 9943), for verifiable records of agent actions. Stewarded today by Action State Group, built to be donated to a neutral home.
