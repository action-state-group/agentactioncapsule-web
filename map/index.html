01 COSE + deterministic encoding

published RFC

Every record and checkpoint is signed as a COSE_Sign1 (RFC 9052). A signature over a digest checks only if the verifier hashes the same bytes the signer hashed, so JSON records are canonicalized with JCS (RFC 8785).

RFC 9995, the COSE Hash Envelope, signs the digest of a preimage held elsewhere; the COSE deterministic encodings Internet-Draft, in preparation, names the deterministic CBOR encoding behind that preimage.

03 AAC capsule

Internet-Draft library released

A Capsule is a JSON record of one agent action that commits to what went in and what came out by digest, never by content; its identity, the capsule_id, is the SHA-256 of its own canonical bytes.

04 Composition

Internet-Draft designed

Composition keeps each format separate and joins them by a shared action digest: who authorized it (WHO), was it permitted (CAN), what the agent did (WHAT), did the runtime enforce it (AUDIT). A capsule fills the WHAT slot, so this layer sits beside the capsule and reads it, rather than under it.

Matching digests alone do not show that the action was authorized or that the record set is complete (accountability-composition-01 §6.2). One WHAT-to-WHO vector set is built; the CAN and AUDIT slots are designed.

05 CLL / MMR + SCITT

Internet-Draft published RFC library released

Each node keeps its own append-only Merkle Mountain Range, signs small checkpoints over it, and can register those checkpoints with a SCITT Transparency Service, while the entries never leave the node.

An inclusion proof shows a record is in the log under a checkpoint; a consistency proof shows the log only grew between two checkpoints. A witness returns a COSE Receipt; the mesh plugin names none by default.

06 Bilateral + settlement

Internet-Draft built, not live

Two parties who do not trust each other each seal only what their own side observed, and a verifier who trusts neither derives from the two records whether they agree; when they differ, the asymmetry is named.

Settlement records add the four legs of a payment with exact amounts and payment references. explain 12 shows the same records checked locally, by the other party, and by anyone with the evidence file.

07 Evidencebook

library released

Keep every record you seal in an append-only log on your own disk, sign a checkpoint over it every N records or T minutes, and hand out a record with its inclusion proof and checkpoint so anyone can check it offline.

evidencebook Go v0.5.0 and the Rust crate 0.0.6 are tagged releases; the mesh plugin does not build on it yet (planned).

08 Judge + grades

Internet-Draft library released

A record may say how much evidence stands behind it; the verifier works that out again from the record's own bytes and reports any claim they do not support.

On the mesh, two answers to a marked pair are compared and a referee can sign a verdict (built, off by default). A verdict is its own record, linked by adjudicates, and never changes the record it judges.

09 History

built, not live designed

A node folds referee verdicts about a peer into counts kept locally, and an opt-in rule, off by default, can stop routing to that peer. Counts in their own units, no ranking and no score.

In a personal agent the person hands one recipient a History of selected deals; history_card/1 carries a stream's checkpoint history with no record content.

10 Reports

Internet-Draft library released

A bundle packages a record with what makes it checkable and says exactly what it left out; selective disclosure withholds single fields without breaking the signature; an evidence request asks another party for a record.

The evidence report is one exchange as a file a stranger checks offline. A report page is drawn only after the file verifies, in words that live outside the evidence.
