The evidence report: one exchange, checked by anyone

One exchange becomes one file. Anyone it is handed to, an auditor, a customer or the other side, can check it on their own machine, offline, with no account. This page shows what such a check covers, what it leaves out, and which verifiers read the file today. The example is a real file from a live two-node run, and the verifier was run on it for this page.

1What it is

An evidence file is one AAC Evidence Bundle (evidence-bundle/v2): the records of one exchange, unchanged, with the signed checkpoint and proofs that place each record in its producer's log.

A verifier reads it offline and reports each claim on its own: the records, their signatures, citation closure, the checkpoint, coverage, membership and, when it is given witness keys, witness receipts.

The report is one readable HTML page drawn from that verifier's result; it does no checking of its own, and the same file can travel as a link fragment, inside an offline page, or as a download.

2Design choices

Chosen: one object, three ways to carry it: in a URL fragment, inside an offline HTML page, or at a hosted URL.
Rejected: a separate format per channel; the draft calls these “transports for one object, not distinct evidence formats”. A fragment is never sent to the server that serves the page. (disclosure-bundle §1, §9)
Chosen: the checkpoint is read only from its signed COSE form (checkpoint.cose); a JSON copy that differs from it fails the file.
Rejected: trusting the checkpoint as the producer wrote it; without a verified signature or witness receipt, coverage and membership are only relative to a checkpoint the producer asserted. (disclosure-bundle §6; capsule-emit evidence_file.py)
Chosen: an inclusion proof for every record, checked at its stated leaf index and against the checkpoint's size.
Rejected: a range proof over the two end records only; an interior record could be deleted or replaced while it still passes. (disclosure-bundle §6, §11)
Chosen: the report page never checks. It draws the result of check_evidence_file and refuses a result whose bundle digest is not the digest of the file it draws.
Rejected: a page with its own checks, or trusting the file's verification member, which the draft makes producer self-report that must not replace independent verification. (disclosure-bundle §10; capsule-viewer README)
Chosen: no witness is trusted by default. The verifier supplies a witness directory; without one no receipt is checked and the result says “not shown”.
Rejected: a built-in list of trusted witnesses; the file would then carry trust the reader never chose. Only a receipt that fails changes the verdict. (capsule-emit evidence_file.py)
Chosen: an export holds one scope (an exchange, a peer, a time window or a record) and refuses when none is given; the whole log only with --all. A scoped file says "selection": "producer-selected".
Rejected: exporting the whole log by default; a file meant for one counterparty would carry every other exchange. (capsule-emit CHANGELOG 0.9.0)
Chosen: records carry digests of the request and the answer. The content is shown only if the holder adds it as a disclosure, which the verifier rehashes and compares with the digest the record committed to. The disclosable fields are model_attestation.compute_attestation.agent_input_digest and agent_output_digest (a SHA-256 over the JCS form of the value); in the example they hold the same values as the effect digests.
Rejected: putting the text in the record; every holder of the file would then hold the conversation. (disclosure-envelope-00 abstract; disclosure-bundle §5)

3What it shows / what it does not

Shows

  • That nothing in a record changed since it was sealed: its capsule_id recomputes from its content.
  • Which key signed each record, and that the signature checks.
  • That the checkpoint is signed and that the file's copy matches what was signed, and whether the records' key is the checkpoint's key.
  • Where each record sits in the log, by an inclusion proof to the range root at the checkpoint's size, once coverage and membership pass.
  • That a witness registered the checkpoint, when the file carries a receipt and the verifier holds that witness's key.
  • That a disclosed request or answer matches the digest its record committed to.

Does not show

  • The text itself: the record holds digests only, unless the holder chooses to disclose it.
  • That the answer was right.
  • Who holds a key in the world: a key says who holds it, not who that is.
  • Anything about the records between the ones a producer chose to export.
  • That the other side recorded the same thing: one file is one node's records, and the verifier reads one file at a time. The two files of the example carry the same request and answer digests under two different keys; comparing them is a separate step.
  • Coverage and membership on the example file today: they fail on the current verifier (see Status).

INVALID

The vector's own README expects exactly this: coverage and membership need an agent-action-capsule that accepts a range root tied to the checkpoint by a consistency proof, and until then the file is INVALID. Its test accepts that state, or VALID once the verifier changes, and nothing else. The provider's file gives the same result.

6Specs

  • Internet-Draft draft-mih-zhang-agent-disclosure-bundle-00 — the Evidence Bundle: transports, closure, disclosure overlay, the three completeness claims, verification.
  • Internet-Draft draft-mih-agent-disclosure-envelope-00 — revealing the content behind a digest-only field without changing the record or its capsule_id.
  • Internet-Draft draft-mih-scitt-agent-action-capsule-05 — the record, its capsule_id and its signature.
  • Internet-Draft draft-mih-scitt-checkpointed-local-log-02 — the local log, its signed checkpoints, and inclusion and consistency proofs.
  • RFC RFC 9942 — COSE Receipts.
  • RFC RFC 9943 — SCITT architecture.
  • RFC RFC 9052 — COSE; the checkpoint and the record signatures are COSE_Sign1.
  • Code action-state-group/capsule-emit — verify --bundle, export, and the evidence-file vectors.
  • Code action-state-group/capsule-viewer — the evidence report page.
