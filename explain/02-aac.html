Agent Action Capsule

A Capsule is a JSON record of one agent action that commits to what went in and what came out by digest, never by content, and whose identity is the SHA-256 of its own canonical bytes.

1What it is

An Agent Action Capsule is a JSON record of one agent action and its outcome, including actions that were refused, blocked, or timed out.

Sensitive content such as prompts, completions, and tool payloads is not carried in the record; it is committed to by SHA-256 digest only.

The Capsule's identity, its capsule_id, is the SHA-256 of its own canonical JSON, so any verifier can recompute it; a later edit shows once that id is checked against a Producer Envelope or receipt made over the original.

2Design choices

Chosen: commit content by digest; the Capsule carries request_digest and response_digest, not the bodies.
Rejected: carrying raw content. A committed Capsule cannot be retracted, so anything admitted is admitted permanently; content that must be checkable later but not disclosed now is committed as a digest. (Draft §5, §14.1)
Chosen: a signer-independent identity: capsule_id is SHA-256 over plain JCS of the Capsule with only capsule_id removed, and a COSE_Sign1 Producer Envelope signs those raw 32 bytes.
Rejected: making the signature part of the identity. Envelopes are not in the preimage, so adding, removing, or replacing one never changes capsule_id. (Draft §3.1, §5.1)
Chosen: status: "confirmed" requires a response_digest over the response actually observed.
Rejected: a status label on its own. Without the bound response a producer could present an attempt as a completion; a verifier treats confirmed-without-digest as a failure. (Draft §5.3, §6 check 3)
Chosen: for inference_completion, digest the request body as received at the serving boundary and the completion body as returned, and record who vouches in effect_attestation.
Rejected: grading a host's report as a direct observation. host_served_observed means the producer saw the host's report, not the effect boundary; it grades equal to runtime_claimed, below gate_executed. (Draft §5.3)
Chosen: a hashed chain block with exactly one parent and a registered relation; an epoch change is an ordinary Capsule with relation: "epoch_opens".
Rejected: multiple parents or a new statement type for epoch boundaries. Citations outside the producer's own stream go in references instead. (Draft §5.2.2, §5.5.4, §5.5.5)
Chosen: one declared construction: format_version: "4" and canonicalization_id: "jcs", checked before any digest is computed.
Rejected: accepting other declarations. Any other format, or an absent, empty, unknown, or withdrawn "jcs-n" canonicalization, fails closed. (Draft §2)

3What it shows / what it does not

Shows

  • That the carried capsule_id matches the record: the verifier recomputes it and never trusts the carried value (§6 check 2). That the record is unchanged since sealing needs more: a verified Producer Envelope (§3.1) or a receipt over the original id.
  • A confirmed effect carries a digest of the response that was observed.
  • The assurance modes the bytes support: a verifier rederives assurance from the evidence present and reports overclaims (§6 check 7).
  • That effect_attestation is present wherever the effect status requires it (§6 check 5).
  • Which earlier Capsule this one follows, and where a configuration epoch starts.

Does not show

  • That the effect happened in the world. host_served_observed records a runtime's report of completion, not an observation of the effect boundary.
  • What the request or completion said. A digest can be checked only by someone who holds the body.
  • That every action was recorded. A Capsule on every verdict, refusals and blocks included, is a producer obligation (§5.5.3); a Capsule shows this action was recorded, not that none were left out.
  • That the stated effect_attestation is true. Who vouches is the producer's statement; the verifier checks only that it is present where required.
  • That the signing key was authorized for the operator. A valid envelope signature proves which key signed; authorization is the caller's policy (Draft §3.2).
  • Privacy for low-entropy values: a digest of a user or session identifier can be reversed by guessing, so identity must be excluded, not digested (Draft §14.1).

4Example

A conformance vector for the inference_completion effect, confirmed and attested host_served_observed. Its expected result is ok: true with no findings, and the recomputed capsule_id equals the carried one. The two digests are filler values (all 1s, all 2s); the vector tests the record, not real bodies. It carries no chain block, so its ledger mode is standalone.

FieldTypeMeaning
action_idstringStable identifier of the action within one producer ledger.
action_typestring"decide": a disposition was required ("fyi" is informational).
assuranceobjectClaimed attestation, effect, and ledger modes; a verifier rederives each and reports overclaims.
canonicalization_idstringMust be exactly "jcs": plain RFC 8785 JCS for every digest.
capsule_id64 hexSHA-256 over JCS of the Capsule minus this field; recomputed, never trusted.
developerstringThe agent identity and version that acted.
dispositionobjectGate outcome: who disposed it, the human-in-the-loop flag, and the verdict class.
effect.typestringRegistered effect type; here an inference request whose effect is producing a completion.
effect.statusstring"confirmed": result observed and bound, so response_digest must be present.
effect.effect_attestationstringProducer-stated grade: the serving host's runtime reported the completion.
effect.irreversibility_classstringOrdered consequence class; "two_way" is the lowest.
effect.request_digest64 hexSHA-256 of JCS of the request body as received.
effect.response_digest64 hexSHA-256 of JCS of the completion body as returned.
format_versionstringSerialization suite; must be exactly "4".
operatorstringThe accountable tenant (a placeholder in this vector).
spec_versionstringThe profile text the Capsule conforms to; never selects an algorithm.
timestampstringRFC 3339 UTC time with "Z".

5Specs

  • Internet-Draft draft-mih-scitt-agent-action-capsule-05 — the Capsule, its identity, the effect record, chaining, epochs, and Class 1 verification.
  • Internet-Draft draft-mih-sokolov-scitt-payload-binding-05 — the declared canonicalization the Capsule's digests rely on (page 04).
  • RFC RFC 8785 — JSON Canonicalization Scheme (JCS).
  • RFC RFC 9052 — CBOR Object Signing and Encryption (COSE): the Producer Envelope is a COSE_Sign1.
  • RFC RFC 9943 — SCITT architecture: registering the Capsule ID with a Transparency Service.
  • RFC RFC 9942 — COSE Receipts.
  • Code action-state-group/agent-action-capsule — draft source and conformance vectors.
